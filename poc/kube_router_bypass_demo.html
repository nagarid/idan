kube-router / k3s NetworkPolicy Bypass

CVE-CANDIDATE CAP_NET_RAW NO PRIVILEGED Source IP Spoofing via Raw Sockets — kube-router KUBE-NWPLCY chain has no interface-based anti-spoofing

What you're watching

A pod with only CAP_NET_RAW (the default Kubernetes capability — no privileged:true) bypasses a NetworkPolicy enforced by kube-router.

StepResult
allowed-source (10.244.0.10) → target✓ DELIVERED (baseline)
blocked-source (10.244.0.20) → target, normal socket✓ BLOCKED (policy works)
blocked-source → target, raw socket spoofing src=10.244.0.10✗ BYPASSED — target received BYPASSED-KUBE-ROUTER

Root Cause

KUBE-NWPLCY-test:
  -m set --match-set KUBE-SRC-<hash> src   ← source IP only, no -i <interface> check
  -d <target> -j MARK --set-xmark 0x10000

# Calico (protected):
cali-from-ep-*:
  -i cali<hash> ! -s <pod_ip> -j DROP      ← interface AND IP — spoofing blocked

iptables Counters (end of run)

Chain KUBE-NWPLCY-test:
  2 pkts MARK  src=10.244.0.10 → 10.244.0.30   ← 1 legit + 1 spoofed

Chain KUBE-POD-FW-test:
  2 ACCEPT  mark match 0x10000/0x10000        ← both packets accepted
  1 DROP                                       ← real blocked-source dropped

Fix

iptables -I KUBE-ROUTER-FORWARD 1 -i <pod_veth> ! -s <pod_ip> -j DROP

Or apply restricted PodSecurity Standard to drop CAP_NET_RAW cluster-wide.
